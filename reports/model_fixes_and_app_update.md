# Model Training Fixes and Application Update

This report records a review of model training in Tasks 5-8, the fixes made, how the results changed,
and the redesign of the Streamlit application (Task 9). The task reports in this folder
(`feature_engineering_report.md`, `model_comparison_report.md`, `evaluation_report_dnn.md`,
`xai_report.md`) were regenerated by rerunning the notebooks after these fixes.

## 1. Problems found in model training

| # | Problem | Where | Effect |
|---|---------|-------|--------|
| 1 | **Applicants shared between train and test.** Each applicant applied to several universities, and the university data was split row by row. 90.7% of test rows belonged to an applicant who also had rows in the training set. | Task 5 split | Test scores measured partly on people the models had already seen. |
| 2 | **Hidden leak through frequency encoding.** `department` / `specialization` are free text; 22.9% of rows use a specialization spelling that only one applicant wrote. Frequencies were counted over *all* rows (test included), so for those rows the "frequency" equalled the number of universities that applicant applied to, a signal correlated with the outcome (r = -0.18) that the app can never supply for a new user. | Task 5 encoding | Inflated the university models, mainly XGBoost (0.80 test ROC-AUC). Adding the application count directly reproduces the lift (validation ROC-AUC 0.754 → 0.794). |
| 3 | **Integer label encoding of categories.** `univname`, `department` and `specialization` were fed to the models as alphabetical integer codes. Tree models can split on them; for Logistic Regression, SVM and the DNN the order is meaningless. | Task 5 encoding | Logistic Regression reached only 0.61 ROC-AUC; the DNN trailed XGBoost. |
| 4 | **Graduate model used 3 features.** The hand-weighted `admit_chance_index` was a candidate feature; the correlation filter (\|r\| > 0.90) then dropped CGPA, GRE, LOR and research, leaving `admit_chance_index`, `toefl_score`, `sop`. | Task 5 selection | Models could not learn how much each attribute matters; they inherited fixed Task 5 weights. |
| 5 | **Model selection on the test set.** The "best" Task 6 model and the Task 7 DNN-vs-ML comparison were chosen by test ROC-AUC. Graduate feature importance was also computed on all 500 rows, test rows included. | Tasks 5-7 | Slightly optimistic reported numbers. |
| 6 | **Statistics computed on all rows.** Category vocabularies and frequencies were fitted on all rows; Task 6 filled missing values with all-row medians. | Tasks 5-6 | Minor; not clean practice. |
| 7 | **Library version mismatch.** Models were pickled with scikit-learn 1.6.1 but the environment had 1.9.1 (`InconsistentVersionWarning`); `requirements.txt` was unpinned. | Environment | Risk of models failing to load or behaving differently. |
| 8 | **CGPA scale bug in the app.** A CGPA on a 4- or 100-point scale was passed to the graduate model as if it were out of 10. | `app.py` | Wrong graduate predictions for non-10-point applicants. |

## 2. Fixes

**Task 5 (feature engineering)**
- Train / validation / test split saved as a `split` column and reused by Tasks 6-8:
  - University: **by applicant** with `GroupShuffleSplit` (64 / 16 / 20) — 34,207 / 8,579 / 10,741 rows; no applicant appears in more than one part (checked with an assertion).
  - Graduate: stratified 60 / 20 / 20 on the Task 6 label (300 / 100 / 100 rows); the test rows are the same 100 as before.
- `fit_score` cohort statistics still come from training rows only.
- Categorical encoding, fitted on **training rows only** and saved to `outputs/task5_output/category_encodings.json`:
  - One-hot: `program` (4), `univname` (54), `rank_tier`.
  - `department` / `specialization`: one-hot for levels with ≥ 200 training rows (27 / 9 columns; rarer levels share an all-zero "other" encoding) plus a training-row frequency (unseen levels → 0).
  - Integer label encoding removed.
- Feature selection: importance computed on training rows only for both datasets. University: the 95%-cumulative-importance rule runs on numeric features; one-hot groups are kept whole (105 features = 11 numeric + 90 one-hot). Graduate: `admit_chance_index` kept as a reference column only; selected features are `cgpa`, `gre_score`, `toefl_score`, `lor`, `sop`.

**Task 6 (machine learning)**
- Uses the Task 5 split; best model = highest **validation** ROC-AUC (`val_roc_auc` column); all other metrics are test-set numbers. Missing values filled with training-row medians.

**Task 7 (deep learning)**
- Uses the Task 5 validation rows for early stopping and configuration choice (previously 15% carved from training). The DNN-vs-ML comparison uses the validation-selected ML model and reports `val_roc_auc`.

**Task 8 (explainable AI)**
- Uses the Task 5 split and the validation-selected ML model. Counterfactuals now change the raw graduate attributes directly.
- The selected university model is now an RBF SVM (23,722 support vectors, ~700 predictions per second), so sample sizes were reduced to keep the run to ~15 minutes: SHAP on 60 university applicants with 25 background rows (graduate: 100 / 100), permutation importance on 1,000 university test rows. The university SHAP ranking is therefore indicative. Plot sizes are capped at the top 15 features.

**All notebooks** now run locally from `notebooks/`, reading and writing `../outputs/taskN_output/` and `../reports/` (Colab paths still work), and only zip/download deliverables in Colab.

**Environment**: `requirements.txt` pins the exact versions the models were trained with (Python 3.14; `tensorflow==2.22.0rc0` is a pre-release).

| Dataset | Model | Before | After (validation) | After (test) |
|---------|-------|-------:|-------------------:|-------------:|
| University | **DNN** | 0.753 | **0.787** | **0.780** |
| University | SVM | 0.708 | 0.769 | 0.760 |
| University | XGBoost | 0.800 | 0.755 | 0.746 |
| University | Logistic Regression | 0.608 | 0.750 | 0.743 |
| University | Random Forest | 0.767 | 0.741 | 0.726 |
| University | Decision Tree | 0.726 | 0.606 | 0.597 |
| Graduate | **Logistic Regression** | 0.948 | 0.928 | **0.956** |
| Graduate | DNN | 0.950 | 0.931 | 0.946 |
| Graduate | SVM | 0.934 | 0.915 | 0.935 |
| Graduate | Random Forest | 0.922 | 0.919 | 0.930 |
| Graduate | XGBoost | 0.907 | 0.904 | 0.911 |
| Graduate | Decision Tree | 0.873 | 0.782 | 0.788 |

**Interpretation**
- The old university XGBoost score (0.80) was inflated by problems 1 and 2. On the same applicant split, the old feature set scored 0.789 on validation, and almost all of that advantage disappears once the application-count leak is removed.
- With proper encoding, the linear and neural models can use university identity: Logistic Regression +0.135, DNN +0.027. **The DNN is now the best university model** (selected DNN configuration: hidden layers (64, 32), dropout 0.3, L2 1e-3, learning rate 3e-4).
- Graduate: Logistic Regression and the DNN are effectively tied (100-row validation and test sets; a 0.01 difference is about one applicant). Logistic Regression is preferred for simplicity and readable coefficients.
- University fairness checks (program; ranked vs unranked) now show gaps of about 0.10-0.15 and are flagged for review (`xai_report.md`).

## 4. Application redesign (Task 9)

**Structure**: four tabs — *Your profile*, *Your matches*, *Why these results*, *Model details* — under a three-step "how it works" strip. After a successful run the app switches to *Your matches* automatically. The sidebar only asks how many universities to show; model choice is under *Advanced* (defaults: best validation models).

**Profile form**
- Grouped into bordered sections: academic record, test scores, application documents, experience, study plans; every field has help text.
- Fewer inputs: GRE total = verbal + quantitative; research yes/no derived from research years; the target-university rating is only asked if the graduate model uses it.
- Grading-scale picker (out of 4 / 10 / 100) sits outside the form, so CGPA limits and defaults update immediately. CGPA is converted to the 10-point scale for the graduate model (fixes problem 8).
- New *Program* input (the university models use it); searchable department and specialization lists.

**Your matches**
- Summary cards: overall admission outlook (Strong ≥ 70% / Competitive 40-70% / Developing < 40%), top match, and Safe / Target / Reach counts.
- Table with progress bars and a *Category* column (Safe ≥ 70%, Target 40-70%, Reach < 40% admission chance); every column explained in a header tooltip and in a "How to read this table" section. Per-model estimates in a separate section. HTML report and CSV downloads.

**Why these results**
- Plain-language "working in your favour / holding you back" lists and a green/red chart for the overall outlook and for any chosen recommended university (one-at-a-time comparison against the typical applicant, averaged over the ML model and the DNN, in percentage points).
- Explained sections for the model-wide outputs: factor importance (SHAP, permutation), single-applicant examples (waterfall, LIME, dashboards), counterfactual improvements, trust score and fairness checks.

**Model details**: dataset counts, a metric glossary and all Task 5-8 tables and plots.

```bash
cd notebooks
for n in 5 6 7 8; do jupyter nbconvert --to notebook --execute --inplace Task${n}_*.ipynb; done
cd .. && python -m streamlit run app.py
```

Approximate run times on a laptop CPU: Task 5 under 1 min, Task 6 several minutes (mostly the SVM), Task 7 a few minutes, Task 8 ~15 min.
